# Write 工具陷阱

## 1. Write 工具连续调用静默失败

**现象**：连续调用 Write 工具写入多个文件时，只有第一个（或极少数）真正写入磁盘，其余全部被静默丢弃，日志中无 tool_dispatch 记录。

**触发条件**：
- 连续 3 次以上的 Write 调用
- 通过栈帧批量生成文件

**根因**：流式响应中大量 tool_use 内容块可能因缓冲截断，导致后续工具调用未被实际执行。

**日志验证方法**：检查 debug 日志中是否有对应 `tool_dispatch_start_tool=write` 的行。日志中无记录 = 调用未执行。

**正确做法**：
1. 每次 Write 后立即用 `ls` 或 `cat` 验证文件存在
2. 批量文件写入改为分批进行（每批 1-2 个文件），验证通过后再继续下一批
3. 不要假设 Write 工具返回 “ok” = 文件写入成功

**示例**：
错误：
1. Write a.md
2. Write b.md
3. Write c.md
4. 结果可能只有 a.md 成功

正确：
1. Write a.md → ls 验证 → 确认存在
2. Write b.md → ls 验证 → 确认存在
3. Write c.md → ls 验证 → 确认存在
